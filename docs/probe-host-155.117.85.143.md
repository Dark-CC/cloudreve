## 2. SSH 服务

```
SSH-2.0-OpenSSH_9.6p1 Ubuntu-3ubuntu13.20
主机密钥：ssh-ed25519 SHA256:1lRa/RVEcCTdF1/+UzRe9KYTh0eKP8K6zPwO20H2YsM
          ecdsa-sha2-nistp256 / ssh-rsa 亦提供
```

完整握手链路（`ssh -v`）实测全部通过：TCP 建立 → 版本交换 → `KEXINIT` → `sntrup761x25519-sha512` 密钥交换 → 主机密钥校验 → `NEWKEYS` → 服务接受。**只在认证环节停下**：

```
debug1: Authentications that can continue: publickey
root@155.117.85.143: Permission denied (publickey).
```

关键点：服务端**只通告 `publickey`**，没有 `password`、没有 `keyboard-interactive`。也就是说**即使拿到密码也登不进去**，必须往那台机器的 `authorized_keys` 里加公钥（或另有带密码认证的入口）。

## 5. 要真正把「登录」这件事推进，需要你提供什么

现在的卡点只有一个：**这台机器的公钥白名单里没有团队的密钥**。三条可行路线，按推荐顺序：

1. **（推荐）你把公钥加进那台机器**：在 `155.117.85.143` 上执行
   `echo '<团队公钥>' >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys`
   —— 需要你先能登进去一次（控制台 / 商家提供的初始密码）。团队公钥可以向我要，我生成后放进回复。
2. **你直接在平台上把这台机器加为团队机器**：在那台机器上按产品文档跑 `tds start`（见 https://todos.dev/docs/platform-machines ），之后它就会出现在机器列表里，remote shell 可直接用。**这是唯一不依赖 SSH 密钥手工配置的路径**，也最适合后续派活。
3. **开一个密码登录入口**：改 `/etc/ssh/sshd_config` 的 `PasswordAuthentication yes` 并放行（**不建议**在公网 22 上开密码认证，容易被爆破），然后凭据走团队密钥卡（`set_secret`）注入，你不要把密码贴在聊天里。

> 无论走哪条，**凭据一律走团队的 Secrets 页面注入**，不要在对话里贴出密码或私钥。
