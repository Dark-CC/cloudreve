# Cloudreve v4.23.8

本版本补齐了后台**订单管理**与**易支付现金支付渠道**，修复了**增值服务（容量包 / 流量包 / 用户组）填写大小与单价时的两个硬伤**，让**积分可以人工调整并留下流水**，并把**全站做了一次文案体检**——不再有任何翻译 key 以原文（如 `vas.priceStepHint`）的形式出现在页面上。自 v4.23.7 以来的全部变更如下。

This release fills in the admin **order management** and the **易支付 (easypay) cash checkout channel**, fixes **two real defects in how capacity packs, traffic packs and group packs were sized and priced**, makes **points adjustable by hand with a ledger trail**, and gives the interface a **full translation sweep** — no key is printed raw (as `vas.priceStepHint`, say) anywhere anymore. Everything changed since v4.23.7 is listed below.

## 新增 / What's New

### 订单管理 / Order Management

- **后台新增「订单管理」页**：菜单中原「增值服务」下的支付页独立为顶级菜单项，与「任务列表」同一套版式骨架（页头刷新按钮、表格上方的筛选工具条、固定列宽的表格、分页器在表格下方），列出订单号、买家、商品、金额、支付渠道、状态、创建与支付时间。
  *A dedicated "Order Management" admin page, moved out of the settings tabs and rebuilt on the same skeleton as the task list: header refresh, a filter toolbar above the table, fixed column widths, the pager below the table. It lists order number, buyer, product, amount, channel, status and created/paid times.*
- **筛选**：可按状态、用户、日期区间筛选；用户搜索框接受**用户 ID 或邮箱**（邮箱不区分大小写，支持片段匹配），日期选择换成 MUI X 日期选择器。
  *Filter by status, user and date range; the user box accepts a **user ID or an email** (case-insensitive substring). Date inputs use the MUI X date picker.*
- **手工补单全程可审计**：补单总是先向支付网关查询真实状态；**未支付的订单只有在显式勾选「强制」、填写必填原因、并通过二次确认后**才会被落定为已支付，且记录操作人、原因与活动事件；对**已支付**订单重复补单会被拒绝，不会重复发货。
  *Manual reconciliation always asks the gateway first. An unpaid order can only be settled after an explicit force flag, a mandatory reason and a two-step confirmation, and the operator, reason and activity events are recorded. Re-running it on a paid order is rejected instead of delivering twice.*

### 易支付（easypay）现金支付渠道 / 易支付 cash checkout

- **新增易支付网关**，与 Stripe 并列成为现金支付渠道：`submit.php` 的 MD5 签名下单、签名回调（notify / return）并校验金额、与既有订单模型共用一套幂等结算逻辑。
  *易支付 joins Stripe as a cash checkout channel: MD5-signed `submit.php` checkout, signed notify/return callbacks with amount matching, and idempotent settlement shared with the existing order model.*
- **站内扫码支付**：点「购买」不再跳走，弹窗里直接展示二维码与订单号，状态提示在「等待支付 / 已支付 / 已过期」之间轮询切换，到账后自动关窗并刷新结果。
  *Checkout happens in a dialog: the QR code and order number appear in place, the status polls between waiting / paid / expired, and the dialog closes itself once the money lands.*
- **订单状态以服务端查单为准**：轮询时由服务端主动向网关查单并落定，**即使回调丢失也能确认到账**；异步回调降级为加速路径，两条路径共用同一套幂等结算，不会重复到账。
  *Order state is settled by the server querying the gateway, so a lost callback still reconciles. The asynchronous notify is only a fast path; both share one idempotent settlement.*
- **金额换算集中到一处**：单价按站点货币最小单位存储，网关按分为单位收费，两边的换算与校验共用同一份实现，结算与回调校验不会各算一套。
  *Amount arithmetic lives in one place: prices are stored in the site currency's minor units while the gateway charges cents, and checkout and callback verification share the same conversion.*

## 调整 / Changes

### VAS：容量包与积分 / Capacity packs and points

- **容量包 / 流量包 / 流媒体流量包可以选单位了**：以前只能填一个裸数字，单位固定当作「字节」，盯着一串 0 数不清；现在有 KB / MB / GB / TB 单位下拉，输入的量级和显示的一致。
  *Capacity, traffic and stream-traffic packs used to take a bare byte count. They now have a KB/MB/GB/TB unit picker, so the number you type means what it says.*
- **单价可以填小数**：价格输入框此前按整数解析，填 `0.01` 实际存成 `0`（等于「不可购买」）；现在以主单位编辑、以最小单位存储，最小可填到 0.01。
  *Prices used to be parsed as integers, so `0.01` was silently stored as `0` (that is, not purchasable). Prices are now edited in major units, stored in minor units, down to 0.01.*
- **积分改为「调整积分 + 流水审计」**：后台用户详情里可以按正负增量调整积分，每一次调整都写进积分流水（类型为「调整」）并伴随一条活动事件，与消费、兑换码出现在同一个账本里；调整会让余额变成负数时直接拒绝。
  *Points are adjusted by a signed delta from the user detail page. Every change lands in the points ledger as an "adjustment" next to purchases and gift codes, with an activity event; an adjustment that would drive the balance negative is refused.*

### 文案与缓存 / Translation and caching

- **补齐 88 处缺失的翻译 key**：13 种语言逐个补齐，后台的支付订单、易支付设置、增值服务等模块不再有任何 key 以原文形式显示（此前会出现 `paymentOrders.userSearch` 这样的字样）。
  *Eighty-eight missing keys are filled in across all 13 locales, so the payment order, 易支付 and VAS screens no longer print a raw key such as `paymentOrders.userSearch`.*
- **修掉「新文案永远看不到」的缓存病根**：前端翻译走了 7 天的 localStorage 缓存，而缓存版本号取自一个从不变化的占位版本号，于是**早于新 key 访问过站点的浏览器会一直读到旧词条**。现在每次构建都会换新的缓存键，发版后新增文案立刻可见。
  *Translations were cached in localStorage for seven days keyed by a placeholder version that never changed, so a browser that visited before a key was added kept reading the stale bundle. Every build now carries a fresh cache key, and new strings show up right after a deploy.*
- **订单页弹窗按钮不再显示英文 `cancel` / `close`**：这两个调用点指向了一个没有该 key 的命名空间，现已改为通用命名空间下的中文本地化按钮。
  *The order dialogs pointed `cancel` / `close` at a namespace without those keys and rendered the raw English word; they now use the localized common namespace.*

### 移动云盘存储策略 / China Mobile Cloud Drive policy

- **新增存储策略类型「移动云盘」**，并对该类型实施**严格直连**：上传与下载都由浏览器直接与云盘通信，本站不转发任何字节。策略新建向导里不再出现多余的 Endpoint 字段（驱动会从凭据推导云盘主机），凭据只需 `Authorization` 与 `x-yun-app-key`。
  *The "China Mobile Cloud Drive" policy type ships with **strict direct-connect**: the browser talks to the drive directly and this site never relays a byte. The wizard no longer asks for an Endpoint (the host is derived from the credentials); the credential is the `Authorization` header plus `x-yun-app-key`.*
- **「获取直链」改由本站地址下发**：链接留在本站域名下（`/f/:id/:name`），访问时 **302** 跳到云盘签名地址，链接长期有效，每次访问重新签发。
  *Direct links are handed out under this site's own domain and **302** to a freshly signed drive URL on access, so they stay valid.*
- **文件夹也能取直链**：用户组设置中的「文件夹直链」开关可编辑并持久化，开启后文件夹展开为其中每个文件的 `/f/...` 链接，而不是报「实体不存在」。
  *The group setting for folder direct links is editable and persisted; with it on, a folder expands into one `/f/...` link per file underneath instead of failing with "entity not found".*
- **秒传复用缩略图**：共享同一源实体的秒传上传复用已有缩略图实体，不再重复写入同名对象导致任务失败并永久关掉该文件的缩略图。
  *Instant uploads sharing one source entity reuse its existing thumbnail instead of re-writing the same blob, which used to fail the task and permanently disable thumbnails for that file.*
- **分片上传跳过未签发地址的分片**：存储端没有为某个分片签发地址时，上传器跳过该分片，而不是拿空地址去 PUT 后整体失败。

## 兼容性 / Compatibility

- **新增菜单与页面是纯增量**：不启用易支付的站点在升级后支付行为与 v4.23.7 一致，Stripe 渠道不受影响。
- 订单管理页会新增一张订单表与其索引——升级时数据库结构会**自动迁移**，升级前照常建议先备份。
- 容量包 / 流量包的单位选择只改变**输入方式**，库里存的仍是字节数；已有商品的数据与价格不受影响。
- 积分的人工调整走既有积分流水表，不改变用户积分本身的语义，也不需要数据迁移。
- 移动云盘策略仍是纯增量能力：没有创建该类型策略的站点，行为、数据与界面与 v4.23.7 完全一致。
- *The new menu and pages are additive: sites that do not enable 易支付 keep v4.23.7 checkout behaviour, and the Stripe channel is untouched. The order table migrates automatically on upgrade — back up first as usual. The unit picker only changes the input gesture; byte counts in the database are unchanged. Point adjustments reuse the existing ledger. The cloud drive policy remains purely additive.*

## 已知限制 / Known Limitations

- **易支付的三个渠道表现不同**：`wxpay` 网关会返回真正的二维码内容，可以在站内直接画出来；`alipay` / `qqpay` 网关只给一个收银台页面地址，没有二维码可画——弹窗会显示「该渠道未返回二维码」并提供「打开收银台」按钮（新标签页），原页面的轮询照常进行，付款后仍会自动变为「已支付」。
  *Channel behaviour differs: `wxpay` returns real QR content that can be drawn in place, while `alipay` and `qqpay` only return a cashier page. The dialog then says so and offers an "open cashier" button in a new tab, while the original page keeps polling and still flips to paid.*
- **小程序深链（`urlscheme`）未实测**：代码已支持，但当前商户未返回该字段。
- **移动云盘策略下不能打包下载**：zip 与批量下载不可用，只能逐个下载文件。
- **存量直链不受追溯影响**：本次之前取到的本站 `/f/...` 链接照常可用。
- *Desktop and Android builds ship through their own channels (`desktop-v*` / `android-v*`). Archiving stays unavailable on the direct-connect policy.*

## 升级 / Upgrade

**Docker / Docker Compose** — 只需换镜像：

```bash
docker pull ghcr.io/dark-cc/cloudreve:v4.23.8
```

或使用迁移脚本（自动备份 compose 文件、换镜像、重启）：

```bash
curl -sSL https://raw.githubusercontent.com/Dark-CC/cloudreve/baixiong/migrate.sh | sh -s -- /path/to/compose/dir
```

**二进制** — 从下方 [Downloads](#downloads) 下载对应平台压缩包，停止服务、替换二进制、重启即可。`data/` 目录（SQLite、上传文件、`conf.ini`）不受影响。

**升级后建议**：浏览器强刷一次（或清掉站点数据）以确保前端资源与翻译缓存一并更新到本版。

*Docker users only need to swap the image; binary users stop the service, replace the binary and restart. `data/` is untouched. After upgrading, hard-refresh the browser once so the static assets and translation cache both move to this build.*
