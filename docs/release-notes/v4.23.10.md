# Cloudreve v4.23.10

本版本修好了**站点公告里写的样式全部丢失**的问题：管理员把带 `<style>` 栏的完整 HTML 文档粘进公告，用户看到的却是没有排版的裸文字。自 v4.23.9 以来的全部变更如下。

This release fixes **styling being stripped from the site announcement**: an admin pasting a full HTML document with a `<style>` block saw it render as unstyled plain text. Everything changed since v4.23.9 is listed below.

## 修复 / Fixes

### 站点公告保留受控 CSS / Scoped CSS in the site announcement

- **根因**：v4.23.9 的白名单把 `style` 标签和 `style` 属性都排除了（当时的理由是「任意 CSS 可以盖住整个视口、或通过 `url()` 外带数据」）。这个理由依然成立，但一刀切的结果是**连正常排版也一起没了**——公告最常见的用法恰恰是一份带样式的通知卡片。
- **做法不是放行，而是隔离**：`<style>` 的内容会被解析成规则表，逐条按属性白名单与属性值黑名单过滤，然后**给每条选择器加作用域前缀** `[data-cr-announcement]`，再输出回一个 `<style>`，由公告容器承载这个属性。样式只能作用于公告容器内部，改不到站点其它部分。
  *It is isolated, not merely allowed: the `<style>` body is parsed into rules, each declaration filtered through a property allow-list and a value deny-list, every selector prefixed with `[data-cr-announcement]`, then emitted as a single `<style>` carried by the announcement container. Styles cannot escape it.*
- **写配置与读配置两侧都过滤**，且过滤是幂等的：已加过前缀的公告再清洗不会重复叠加，因此后台保存、接口下发、前端二次过滤三层可以叠加而不必互相假设。
- **仍然禁止**：`<script>`、所有 `on*` 事件属性、`javascript:` / `vbscript:` / `data:` 协议、`@import`、`expression()`、`behavior`、`-moz-binding`，以及**一切外链资源**（`url(`、`image-set(`、`@font-face`）—— 公告不能向第三方发起请求，也就不能用它做数据外带或追踪。
- **仍然丢弃**：`@keyframes` / `@page` / `@charset` / `@layer` 等其余 `@` 规则（`@media` / `@supports` 保留并递归处理）；视口单位（`vh` / `vw` / `vmin` / `vmax`）一律丢弃，公告撑不满整屏。
- **页面级选择器改写或丢弃**：`html` / `body` / `:root` 开头的选择器改写为作用于公告容器本身（这样「整页灰底、居中」这类写法在弹窗里表现为「卡片灰底、居中」）；依赖页面状态的选择器（`body.dark`、`html[data-theme]`、`:root.dark`）无法在容器内安全表达，整条丢弃——公告在深色主题下继续使用自己的配色。
- **允许的 CSS 属性**：颜色、背景色、边框（含圆角）、阴影、内边距、外边距、字号字重字体栈、行高、宽高与 `max-*`、`display` / `flex` / `grid` 布局、`gap`、`text-align`、`overflow`、`opacity`、`transform`、`transition`、`white-space`、`word-break`、自定义属性（`--x: …`）等；`rgba()`、`calc()`、`var()`、`linear-gradient()`、`!important` 都保留。
- **大小上限**：单个 `<style>` 最多 64KB、500 条规则、3 层嵌套，超出部分丢弃，避免极端公告拖慢页面。
- **文首提示**：v4.23.9 的发布说明把 `style` 列在「禁止的标签」里；本次起该条不再适用，`style` 与 `style` 属性在**上述隔离与过滤之下**被允许。

## 兼容性 / Compatibility

- 纯增量：没有 `<style>` 的公告行为不变；已存在的公告不需要任何迁移。
- 本次不涉及数据库结构变更，无需数据迁移；升级前照常建议先备份。
- 公告样式改动不会影响站点自身样式表，公告容器之外的元素不会因公告内容而变化。
- *Additive: announcements without `<style>` behave exactly as before, no migration is needed, and there are no schema changes. Back up first as usual.*
