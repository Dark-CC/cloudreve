# Cloudreve v4.23.6

本版本新增登录/注册验证码的**极验 GeeTest v4（行为验证 4.0）**支持，将后台 VAS（积分与增值服务）设置页对齐 Pro 版形态并移除「手动积分调整」，将**目录级存储策略**的用户体验对齐 Pro 版，新增从 Pro 平移库的自动补齐，同时精简了 CI 工作流。自 v4.23.5 以来的全部变更如下。

This release adds **GeeTest v4 (behavior verification 4.0)** as a captcha provider for login/registration, realigns the admin VAS (credits & value-added services) settings page with the Pro edition layout while removing the "manual credit adjustment" feature, aligns the **per-directory storage policy** experience with the Pro edition, adds automatic backfill for databases migrated from Pro, and trims the CI workflows. Everything changed since v4.23.5 is listed below.

## 新增 / What's New

### 验证码 / Captcha

- **极验 GeeTest v4 验证码支持**：
  - **后台设置**：管理面板「设置 → 验证码」的验证码类型新增「极验 GeeTest v4」选项；选择后填写官方控制台获取的 `captcha_id`（验证 ID）与 `captcha_key`（验证密钥）。
    *Admin dashboard → Settings → Captcha: the provider selector gains a "GeeTest v4" option; GeeTest takes the `captcha_id` and `captcha_key` from the GeeTest console.*
  - **前端渲染**：用户端登录、注册、找回密码等开启验证码的表单会按后端下发的类型自动渲染极验 gt4.js 组件（`static.geetest.com/v4/gt4.js`），完成行为验证后方可提交；管理后台登录页同步支持。
    *The frontend renders the GeeTest gt4 widget whenever the backend advertises the geetest provider (login, registration, password recovery, admin sign-in included).*
  - **服务端校验**：提交时组件回调返回的 `captcha_output`、`lot_number`、`pass_token`、`gen_time` 四个参数随请求一并提交，服务端以 `sign_token = HMAC-SHA256(captcha_key, lot_number)` 规范向极验官方 `/v4/validate.php` 端点（`api2.geetest.com`，失败自动回退 `api.geetest.com`）发起二次校验，校验失败按失败关闭（fail-closed）拒绝请求；`gen_time` 超过 24 小时的票据本地直接拒绝。
    *The server verifies the four widget callback fields against GeeTest's official validate endpoint (`api2.geetest.com` with `api.geetest.com` fallback) using the HMAC-SHA256 sign_token scheme, and rejects the request on any validation failure (fail-closed); tickets older than 24 h by `gen_time` are rejected locally.*
  - **兼容性**：原有各验证码类型（普通 CAPTCHA、reCAPTCHA、Turnstile、腾讯云、Cap）行为不变；未配置或配置为关闭时与旧版一致。全部 13 种界面语言文案同步。
    *Existing providers are unchanged; i18n strings for all 13 locales included.*

### 积分与支付 / Credits & Payments

- **积分系统开关（`score_enabled`）**：后台「积分与增值服务」新增开关，默认开启。关闭后：分享创建时无法再设置积分价格（接口返回 `Credit system is disabled`）、已定价分享无法被购买、用户端分享定价面板隐藏；站点配置（`/api/v4/site/config/1`）显式返回 `score_enabled` 供前端感知。
  *Credit system toggle (`score_enabled`), on by default. When off: priced shares can no longer be created (the API returns `Credit system is disabled`), existing priced shares cannot be purchased, and the pricing panel is hidden in the share dialog. The site config now exposes `score_enabled` for the frontend.*
- **站点货币设置**：支付设置区新增货币一键选择（14 种：美元、人民币、欧元、英镑、日元、港币、澳元、加元、新加坡元、韩元、卢布、泰铢、越南盾、印度卢比），选中即自动填充货币代码 / 符号 / 最小单位三个键（`payment_currency_code` / `payment_currency_mark` / `payment_currency_unit`）。展示货币站点级生效（商店、分享定价、购买页均使用），Stripe 结算货币仍是独立配置；旧站点未设置时自动回退 `payment_stripe_currency`，升级无感。
  *Site-wide currency settings: the payment section gains a one-click currency picker (14 currencies). Picking one fills the currency code / mark / unit keys (`payment_currency_code` / `payment_currency_mark` / `payment_currency_unit`). The display currency applies site-wide (shop, share pricing, purchase pages), while the Stripe settlement currency stays separately configured; existing sites fall back to `payment_stripe_currency`, so upgrades are seamless.*
- **支付提供商区块**：VAS 设置页新增支付提供商区块，与 Pro 形态一致。当前后端仅支持 Stripe，菜单中**仅保留 Stripe 一项**（选中出现密钥配置表单并实际生效）；微信官方扫码支付、支付宝与自定义支付渠道在后端支持落地前**暂时隐藏**，实现后再恢复展示。
  *Payment providers section: the VAS page gains a providers block matching the Pro layout. Only Stripe is wired up today and is the sole entry shown in the picker (selecting it reveals the key fields and actually works); WeChat Pay, Alipay and custom channels are hidden until their backend support lands, then they will reappear.*

### 存储策略 / Storage Policy

- **文件列表工具栏「切换目录存储策略」按钮**：在「我的文件」中，任何目录的工具栏上都有「切换目录存储策略」按钮。点开后是一个菜单：默认项「跟随上级目录（继承）」会显示当前生效的策略名，下面直接列出你的用户组可用的所有存储策略（默认策略带「用户组默认」标注）。**点选即绑定，无需弹窗确认**，绑定/解绑后 snackbar 反馈并刷新列表，当前绑定项在菜单里带勾选标记。也可从右键菜单「更多操作 → 上传存储策略」进入同一功能。
  *In "My Files", every directory now has a "switch directory storage policy" button in the file list toolbar. It opens a menu: the default "follow parent directory (inherit)" entry shows the currently effective policy, followed by every policy your user group is allowed to use (the default one labeled "user group default"). Clicking binds immediately — no dialog, no confirmation — with a snackbar and list refresh afterwards, and the bound entry is check-marked. The same function is reachable from the context menu under "More actions → upload storage policy".*
- **进入不同策略目录时的提醒**：进入一个绑定（或继承）了与当前位置不同存储策略的目录时，右下角 toast 提示「当前目录使用存储策略：X」。提醒可在 **设置 → 存储 → 存储策略变更提醒** 开关控制（默认关闭）。同目录刷新不会重复弹出。
  *When you enter a directory whose effective storage policy differs from where you were, a toast tells you "this directory uses storage policy: X". The reminder has a toggle under **Settings → Storage → storage policy change reminder** (off by default). Refreshing inside the same directory does not re-trigger it.*
- **设置页恢复「存储」标签页**：`/settings` 新增「存储」页，包含存储配额条、**首选策略**选择器（新文件默认走哪个策略）与上述提醒开关。该页面的组件在之前的版本重构中遗留未挂载，本次恢复。
  *A "Storage" tab returns to `/settings`, with the storage quota bar, the **preferred policy** selector (which policy new files default to) and the reminder toggle above. This page's component had been left unmounted in an earlier refactor; it is restored.*

### 迁移 / Migration

- **Pro 库自动补齐（用户组存储策略绑定自动平移）**：从 Cloudreve Pro（≤ v4.18）平移过来的数据库会遗留旧版 `group_storage_policies` 关联表，而 fork 使用 `group_allowed_policies` 加 `groups.storage_policy_id`，导致平移后所有走用户组策略的上传一律报 50001，需手工修复。现在程序启动时会自动检测旧表（MySQL / PostgreSQL / SQLite）并幂等平移绑定关系，初次迁移链路与已升级 schema 的快速路径均覆盖；已在真实 Pro v4.18 数据（SQLite、PostgreSQL）上验证含上传全链路与重复重启幂等。
  *Databases migrated from Cloudreve Pro (≤ v4.18) keep the legacy `group_storage_policies` join table while the fork expects `group_allowed_policies` plus `groups.storage_policy_id`, leaving every grouped upload failing with 50001 until fixed by hand. `repairProGroupPolicyBindings` now detects the legacy table at startup (MySQL / PostgreSQL / SQLite) and ports the bindings idempotently, from both the initial migration chain and the up-to-date-schema fast path; verified against real Pro v4.18 data on SQLite and PostgreSQL, including full upload round-trips and idempotent restarts.*

## 调整 / Changes

- **VAS 设置页对齐 Pro 形态**：`/admin/settings?tab=vas` 重排为 Pro 版结构——积分与增值服务（积分开关、积分价格、分享积分汇率、积分商店兑换率）、支付设置（货币三键、Stripe 表单）、支付提供商、产品（四张 SKU 表格：积分、容量、会员组、存储产品）、礼品码管理。
  *The VAS settings page is restructured to match the Pro edition: credits & VAS (toggle, credit price, share score rate, shop redemption rate), payment settings (currency keys, Stripe form), payment providers, products (four SKU tables: credit, capacity, group, storage), and gift codes.*
- **分享定价面板按积分开关显隐**：文件分享对话框中的积分价格字段在积分系统关闭时隐藏，开启时恢复。
  *The share pricing panel hides the credit price field when the credit system is off.*
- **分享对话框改版与「公开分享」选项更名**：分享对话框的高级选项区改为由对话框操作区的齿轮按钮控制展开（收起时展示访问权限区）；「收录到公开目录」更名为「公开到分享广场」，与发现页更名保持一致。
  *The share dialog's advanced options are now toggled from a gear button in the dialog actions (the access section shows when collapsed); "list in public directory" is renamed to "share to Share Plaza", consistent with the Discover renaming.*

## 改进 / Improvements

- **仅有单一可用策略时不再隐藏目录策略入口**：此前用户组只配置了一个策略时，「上传存储策略」入口会被隐藏，用户无从得知也无法调整继承；现在入口保留（对齐 Pro 行为）。
  *When the user group has only one usable policy, the directory policy entry is no longer hidden; it stays available (matching Pro behavior), so inheritance can still be inspected and adjusted.*
- **目录生效策略标记改为公开**：文件列表 API 响应的 `parent.metadata` 现在直接携带 `sys:preferred_policy`，第三方客户端无需再以管理员身份查询。
  *The file listing API now exposes `sys:preferred_policy` in `parent.metadata`, so third-party clients no longer need admin access to learn a directory's effective policy.*
- **CI 工作流精简**：`ci.yml` 改为仅手动触发（`workflow_dispatch`），移除定时任务 `upstream-watch.yml` 与 Dependabot 配置，公开仓库的 Actions 运行记录不再随每次提交增长；发版流程（`release.yml`，tag 触发）不受影响。
  *CI trimmed: `ci.yml` is manual-dispatch only, the scheduled upstream-watch workflow and Dependabot config are removed; the tag-triggered release pipeline is untouched.*

## 移除 / Removed

- **手动积分调整**：完整移除后台「手动积分调整」区块及其链路——路由 `POST /admin/vas/credit`、controller `AdminAdjustCredit`、service、前端组件 `ManualCreditAdjust.tsx`、API 函数与全部 13 种语言的相关 i18n 键。官方 Pro 同位置本无此功能。
  *Manual credit adjustment is fully removed — the `POST /admin/vas/credit` route, the controller, the service, the `ManualCreditAdjust.tsx` component, the API function and its i18n keys across all 13 languages. The Pro edition has no such feature in that spot either.*

## 兼容性 / Compatibility

- 目录绑定的后端链路（`PUT /api/v4/file/policy`、marker 存储）与 v4.23.5 完全一致，仅可见性与展示层变化；升级后已有绑定原样生效。
- `notify_storage_policy_change` 为新增用户设置，缺省 `false`（不提醒），不影响存量用户。
- 验证码新增 `captcha_type=geetest` 类型及极验设置项，缺省仍为原有类型；存量部署升级后行为不变，启用极验需在后台显式选择。
- 积分系统 `score_enabled` 缺省开启、货币键缺省回退 `payment_stripe_currency`，存量部署升级后展示与行为不变。
- *The backend binding path (`PUT /api/v4/file/policy`, marker storage) is unchanged from v4.23.5 — only visibility and presentation moved; existing bindings keep working after upgrade. `notify_storage_policy_change` is a new user setting, defaulting to `false`. The captcha `geetest` provider is opt-in via the admin settings; existing deployments keep their current provider. `score_enabled` defaults to on and the currency keys fall back to `payment_stripe_currency`, so existing sites see no behavior change.*

## 修复 / What's Fixed

- **设置页存储组件遗留崩溃点清理**：存储设置组件内部对未注册站点配置段的请求会在特定路径触发页面脚本错误，随本次挂载一并移除。
  *A leftover request for an unregistered site-config section inside the storage settings component could trigger a page script error; it is removed along with the remount.*

## 已知未实现 / Not Yet Implemented

- **匿名购买付费分享**：Pro 支持未登录用户购买付费分享；社区版 `PaymentOrder` / `SharePurchase` 模型强绑定 `user_id`，落地需 schema 与迁移改造，本版未实现，界面不做假入口。
  *Anonymous purchase of priced shares (a Pro capability) is not implemented: the community `PaymentOrder` / `SharePurchase` models hard-require a `user_id`, so this needs schema and migration work. No fake UI is shipped.*
- **微信 / 支付宝 / 自定义支付渠道**：后端支付通道未实现，相关菜单项已暂时隐藏（仅 Stripe 可用），待后端落地后恢复。
  *WeChat Pay / Alipay / custom payment channels: the backend only supports Stripe; their menu entries are hidden until implemented.*

## 升级 / Upgrade

**Docker / Docker Compose** — 只需换镜像：

```bash
docker pull ghcr.io/dark-cc/cloudreve:latest
```

或使用迁移脚本（自动备份 compose 文件、换镜像、重启）：

```bash
curl -sSL https://raw.githubusercontent.com/Dark-CC/cloudreve/baixiong/migrate.sh | sh -s -- /path/to/compose/dir
```

**二进制** — 从下方 [Downloads](#downloads) 下载对应平台压缩包，停止服务、替换二进制、重启即可。`data/` 目录（SQLite、上传文件、`conf.ini`）不受影响。跨小版本升级时 schema 迁移会在首次启动时自动执行，建议照常先备份。

**启用极验验证码** — 升级后在「后台 → 设置 → 验证码」选择验证码类型为极验 GeeTest v4 并填入官方凭据即可，无需修改任何配置文件。
