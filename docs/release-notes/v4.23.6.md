# Cloudreve v4.23.6

> 草稿：本说明随验证码功能分支提交，正式发版（打 tag）前如有追加变更请同步更新。
> Draft: shipped with the captcha feature branch; update before tagging the release.

本版本主要新增登录/注册验证码的**极验 GeeTest v4（行为验证 4.0）**支持，并精简了 CI 工作流。自 v4.23.5 以来的全部变更如下。

This release adds **GeeTest v4 (behavior verification 4.0)** as a captcha provider for login/registration, and trims the CI workflows. Everything changed since v4.23.5 is listed below.

## 新增 / What's New

- **极验 GeeTest v4 验证码支持**：
  - **后台设置**：管理面板「系统设置 → 登录注册 → 验证码」新增验证码类型选择（`关闭 / 普通 CAPTCHA / GeeTest v4`）；选择 GeeTest 后填写官方控制台获取的 `captcha_id`（验证 ID）与 `captcha_key`（验证密钥）。
    *Admin dashboard → Settings → Login & Registration → Captcha: new provider selector (off / plain CAPTCHA / GeeTest v4); GeeTest takes the `captcha_id` and `captcha_key` from the GeeTest console.*
  - **前端渲染**：用户端登录/注册等开启验证码的表单会按后端下发的类型自动渲染极验 gt4.js 组件（`static.geetest.com/v4/gt4.js`，中文环境自动加载中文语言包），完成行为验证后方可提交；管理后台登录页同步支持。
    *The frontend renders the GeeTest gt4 widget whenever the backend advertises the geetest provider (login, registration, admin sign-in included).*
  - **服务端校验**：登录、注册、找回密码等开启验证码的接口在提交时把组件回调返回的 `captcha_output`、`lot_number`、`pass_token`、`gen_time` 四个参数一并提交，服务端以 `sign_token = HMAC-SHA256(captcha_key, lot_number)` 规范向极验官方 `/v4/validate.php` 端点（`gcaptcha4.geetest.com`，失败自动回退 `api2.geetest.com`）发起二次校验，校验失败按失败关闭（fail-closed）拒绝请求。
    *The server verifies the four widget callback fields (`captcha_output`, `lot_number`, `pass_token`, `gen_time`) against GeeTest's official validate endpoint (`gcaptcha4.geetest.com` with `api2.geetest.com` fallback) using the HMAC-SHA256 sign_token scheme, and rejects the request on any validation failure (fail-closed).*
  - **兼容性**：原「普通 CAPTCHA」行为不变；未配置或配置为关闭时与旧版一致。全部 13 种界面语言文案同步。
    *The existing plain CAPTCHA provider is unchanged; i18n strings for all 13 locales included.*

## 调整 / Changes

- **CI 工作流精简**：`ci.yml` 改为仅手动触发（`workflow_dispatch`），移除定时任务 `upstream-watch.yml` 与 Dependabot 配置，公开仓库的 Actions 运行记录不再随每次提交增长；发版流程（`release.yml`，tag 触发）不受影响。
  *CI trimmed: `ci.yml` is manual-dispatch only, the scheduled upstream-watch workflow and Dependabot config are removed; the tag-triggered release pipeline is untouched.*

## 升级 / Upgrade

**Docker / Docker Compose** — 只需换镜像：

```bash
docker pull ghcr.io/dark-cc/cloudreve:latest
```

或使用迁移脚本（自动备份 compose 文件、换镜像、重启）：

```bash
curl -sSL https://raw.githubusercontent.com/Dark-CC/cloudreve/baixiong/migrate.sh | sh -s -- /path/to/compose/dir
```

**二进制** — 从下方 [Downloads](#downloads) 下载对应平台压缩包，停止服务、替换二进制、重启即可。`data/` 目录（SQLite、上传文件、`conf.ini`）不受影响。跨小版本升级时 schema 迁移会在首次启动时自动执行，建议照常先备份。

**启用极验验证码** — 升级后在「后台 → 系统设置 → 登录注册」选择验证码类型为 GeeTest v4 并填入官方凭据即可，无需修改任何配置文件。
