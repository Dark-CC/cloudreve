# Cloudreve v4.23.6

本版本新增登录/注册验证码的**极验 GeeTest v4（行为验证 4.0）**支持，并将**目录级存储策略**的用户体验对齐 Pro 版形态，同时精简了 CI 工作流。

This release adds **GeeTest v4 (behavior verification 4.0)** as a captcha provider for login/registration, aligns the **per-directory storage policy** experience with the Pro edition, and trims the CI workflows.

## 新增 / What's New

- **极验 GeeTest v4 验证码支持**：
  - **后台设置**：管理面板「设置 → 验证码」的验证码类型新增「极验 GeeTest v4」选项；选择后填写官方控制台获取的 `captcha_id`（验证 ID）与 `captcha_key`（验证密钥）。
    *Admin dashboard → Settings → Captcha: the provider selector gains a "GeeTest v4" option; GeeTest takes the `captcha_id` and `captcha_key` from the GeeTest console.*
  - **前端渲染**：用户端登录、注册、找回密码等开启验证码的表单会按后端下发的类型自动渲染极验 gt4.js 组件（`static.geetest.com/v4/gt4.js`），完成行为验证后方可提交；管理后台登录页同步支持。
    *The frontend renders the GeeTest gt4 widget whenever the backend advertises the geetest provider (login, registration, password recovery, admin sign-in included).*
  - **服务端校验**：提交时组件回调返回的 `captcha_output`、`lot_number`、`pass_token`、`gen_time` 四个参数随请求一并提交，服务端以 `sign_token = HMAC-SHA256(captcha_key, lot_number)` 规范向极验官方 `/v4/validate.php` 端点（`api2.geetest.com`，失败自动回退 `api.geetest.com`）发起二次校验，校验失败按失败关闭（fail-closed）拒绝请求；`gen_time` 超过 24 小时的票据本地直接拒绝。
    *The server verifies the four widget callback fields against GeeTest's official validate endpoint (`api2.geetest.com` with `api.geetest.com` fallback) using the HMAC-SHA256 sign_token scheme, and rejects the request on any validation failure (fail-closed); tickets older than 24 h by `gen_time` are rejected locally.*
  - **兼容性**：原有各验证码类型（普通 CAPTCHA、reCAPTCHA、Turnstile、腾讯云、Cap）行为不变；未配置或配置为关闭时与旧版一致。全部 13 种界面语言文案同步。
    *Existing providers are unchanged; i18n strings for all 13 locales included.*
- **文件列表工具栏"切换目录存储策略"按钮**：在"我的文件"中，任何目录的工具栏上都有"切换目录存储策略"按钮。点开后是一个菜单：默认项"跟随上级目录（继承）"会显示当前生效的策略名，下面直接列出你的用户组可用的所有存储策略（默认策略带"用户组默认"标注）。**点选即绑定，无需弹窗确认**，绑定/解绑后 snackbar 反馈并刷新列表，当前绑定项在菜单里带勾选标记。也可从右键菜单"更多操作 → 上传存储策略"进入同一功能。
  *In "My Files", every directory now has a "switch directory storage policy" button in the file list toolbar. It opens a menu: the default "follow parent directory (inherit)" entry shows the currently effective policy, followed by every policy your user group is allowed to use (the default one labeled "user group default"). Clicking binds immediately — no dialog, no confirmation — with a snackbar and list refresh afterwards, and the bound entry is check-marked. The same function is reachable from the context menu under "More actions → upload storage policy".*
- **进入不同策略目录时的提醒**：进入一个绑定（或继承）了与当前位置不同存储策略的目录时，右下角 toast 提示"当前目录使用存储策略：X"。提醒可在 **设置 → 存储 → 存储策略变更提醒** 开关控制（默认关闭）。同目录刷新不会重复弹出。
  *When you enter a directory whose effective storage policy differs from where you were, a toast tells you "this directory uses storage policy: X". The reminder has a toggle under **Settings → Storage → storage policy change reminder** (off by default). Refreshing inside the same directory does not re-trigger it.*
- **设置页恢复"存储"标签页**：`/settings` 新增"存储"页，包含存储配额条、**首选策略**选择器（新文件默认走哪个策略）与上述提醒开关。该页面的组件在之前的版本重构中遗留未挂载，本次恢复。
  *A "Storage" tab returns to `/settings`, with the storage quota bar, the **preferred policy** selector (which policy new files default to) and the reminder toggle above. This page's component had been left unmounted in an earlier refactor; it is restored.*

## 改进 / Improvements

- **仅有单一可用策略时不再隐藏目录策略入口**：此前用户组只配置了一个策略时，"上传存储策略"入口会被隐藏，用户无从得知也无法调整继承；现在入口保留（对齐 Pro 行为）。
  *When the user group has only one usable policy, the directory policy entry is no longer hidden; it stays available (matching Pro behavior), so inheritance can still be inspected and adjusted.*
- **目录生效策略标记改为公开**：文件列表 API 响应的 `parent.metadata` 现在直接携带 `sys:preferred_policy`，第三方客户端无需再以管理员身份查询。
  *The file listing API now exposes `sys:preferred_policy` in `parent.metadata`, so third-party clients no longer need admin access to learn a directory's effective policy.*
- **CI 工作流精简**：`ci.yml` 改为仅手动触发（`workflow_dispatch`），移除定时任务 `upstream-watch.yml` 与 Dependabot 配置，公开仓库的 Actions 运行记录不再随每次提交增长；发版流程（`release.yml`，tag 触发）不受影响。
  *CI trimmed: `ci.yml` is manual-dispatch only, the scheduled upstream-watch workflow and Dependabot config are removed; the tag-triggered release pipeline is untouched.*

## 兼容性 / Compatibility

- 目录绑定的后端链路（`PUT /api/v4/file/policy`、marker 存储）与 v4.23.5 完全一致，仅可见性与展示层变化；升级后已有绑定原样生效。
- `notify_storage_policy_change` 为新增用户设置，缺省 `false`（不提醒），不影响存量用户。
- 验证码新增 `captcha_type=geetest` 类型及极验设置项，缺省仍为原有类型；存量部署升级后行为不变，启用极验需在后台显式选择。
- *The backend binding path (`PUT /api/v4/file/policy`, marker storage) is unchanged from v4.23.5 — only visibility and presentation moved; existing bindings keep working after upgrade. `notify_storage_policy_change` is a new user setting, defaulting to `false`. The captcha `geetest` provider is opt-in via the admin settings; existing deployments keep their current provider.*

## 修复 / What's Fixed

- **设置页存储组件遗留崩溃点清理**：存储设置组件内部对未注册站点配置段的请求会在特定路径触发页面脚本错误，随本次挂载一并移除。
  *A leftover request for an unregistered site-config section inside the storage settings component could trigger a page script error; it is removed along with the remount.*

## 升级 / Upgrade

**Docker / Docker Compose** — 只需换镜像：

```bash
docker pull ghcr.io/dark-cc/cloudreve:latest
```

或使用迁移脚本（自动备份 compose 文件、换镜像、重启）：

```bash
curl -sSL https://raw.githubusercontent.com/Dark-CC/cloudreve/baixiong/migrate.sh | sh -s -- /path/to/compose/dir
```

**二进制** — 从下方 [Downloads](#downloads) 下载对应平台压缩包，停止服务、替换二进制、重启即可。`data/` 目录（SQLite、上传文件、`conf.ini`）不受影响。跨小版本升级时 schema 迁移会在首次启动时自动执行，建议照常先备份。

**启用极验验证码** — 升级后在「后台 → 设置 → 验证码」选择验证码类型为极验 GeeTest v4 并填入官方凭据即可，无需修改任何配置文件。
