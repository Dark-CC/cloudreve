# Cloudreve v4.23.7

本版本新增**移动云盘（139）存储策略**，并对该类型实施**严格直连**：上传与下载都由浏览器直接与云盘通信，本站不转发任何字节。同时修复了**上传时忽略客户端指定存储策略**的问题、让**右键单个下载直连存储端**、并让后台**存储策略页对未知类型优雅降级**（不再白屏）。自 v4.23.6 以来的全部变更如下。

This release adds the **China Mobile Cloud Drive (139) storage policy** with **strict direct-connect** semantics: uploads and downloads go from the browser straight to the drive, and this site never relays a byte. It also fixes **uploads ignoring the client's storage policy choice**, sends **single-file context-menu downloads straight to the storage provider**, and makes the admin **storage policy page degrade gracefully on unknown types** instead of rendering blank. Everything changed since v4.23.6 is listed below.

## 新增 / What's New

### 移动云盘（139）存储策略 / China Mobile Cloud Drive (139) policy

- **新增存储策略类型「移动云盘」**：后台「存储策略 → 新建」中可选，填写网页端登录凭据（`Authorization` 请求头整行）与 `x-yun-app-key` 即可创建；可选填根目录 `FileID` 把策略限定在云盘内的某个目录下（留空或填 `root` 表示使用整个云盘）。
  *A new "China Mobile Cloud Drive" policy type in the admin storage policy wizard. Create it with the web client's login credential (the full `Authorization` header) and the `x-yun-app-key` value; an optional root `FileID` scopes the policy to one directory inside the drive (leave empty or `root` to use the whole drive).*
- **文件列表、上传、下载、删除、重命名、新建目录、缩略图与秒传**全部实现；分片直传由云盘签发分片地址，前端按签发顺序逐片 PUT，完成后回调本站登记。
  *Listing, upload, download, delete, rename, mkdir, thumbnails and rapid upload are all wired up. Chunked uploads use the chunk URLs the drive signs: the browser PUTs them in order and then calls back into this site to register the file.*
- **登录态失效的错误码**：云盘凭据过期时返回新的错误码 `40099`（`CodeStorageAuthExpired`），提示重新获取凭据，而不是落成一句无头无尾的上传失败。
  *A dedicated error code `40099` (`CodeStorageAuthExpired`) reports an expired drive credential instead of an opaque upload failure.*
- **中文界面与图标**：策略类型显示为「移动云盘」，配套补齐了 10 条此前缺失的 `policy.y139*` 文案（此前策略页直接显示原始 key），并换上新的云盘图标（蓝渐变云体 + 双向同步箭头）。
  *The type is labelled "移动云盘" in the zh-CN UI, the ten previously missing `policy.y139*` strings are added (the page used to show the raw key), and a new drive icon ships with it.*

### 严格直连 / Strict direct-connect

- **上传一律直传**：移动云盘策略无视库里既有的「中转上传」开关，一定返回云盘的签名上传地址；服务端的中转数据入口（`ConfirmUploadSession`）对该类型直接拒绝，客户端硬塞分片也进不来。
  *Uploads always go straight to the drive regardless of the stored "relay upload" setting; the server-side relay entry point (`ConfirmUploadSession`) rejects this type outright, so a client cannot force chunks through this site either.*
- **下载一律直连**：服务端获取下载地址时对该类型**无条件**返回云盘预签名地址（不依赖客户端传 `direct`），任何入口都不会退回中转；右键单个文件下载在浏览器侧也直接跳到云盘地址，且不再对云盘地址套用 CDN 镜像改写（那会毁掉云盘自己的签名）。
  *Downloads resolve to the drive's presigned URL **unconditionally** — the server does not depend on the client asking for `direct`, so no entry point can fall back to relaying. The browser jumps straight to the drive URL for single-file context-menu downloads, and no longer rewrites it against a CDN mirror (which would invalidate the drive's own signature).*
- **两个中转开关锁定**：策略编辑页的「中转上传」与「下载中转」在移动云盘下置灰不可改，并附说明文案，避免管理员误以为打开就能生效。
  *Both relay toggles are disabled with an explanatory note on the policy edit page, so admins are not misled into thinking they can be turned on.*

### 上传按客户端指定策略落地 / Uploads honour the client's policy

- **修复「上传到了错误的存储策略」**：上传对话框会带上当前目录所用的策略 id，此前服务端只认导入与缩略图场景的那一个入口，普通上传完全忽略它，于是绑定了云盘策略的目录里上传的文件仍落到用户组默认策略。现在普通上传会采纳客户端点名的策略——**但仅当该策略在用户所在用户组的允许集合内**，不在集合内、已挂起或类型未知时静默回退默认策略，伪造 `policy_id` 无法越权；负载均衡策略先解析到具体子策略再交给驱动。
  *Fixed uploads landing on the wrong policy: the upload dialog sends the current directory's policy id, which ordinary uploads used to ignore, so files uploaded into a cloud-drive directory still landed on the group default. Ordinary uploads now honour the named policy — **only when the uploader's group is allowed to use it**; otherwise (not allowed, suspended, unknown type) they silently fall back to the default, so a crafted `policy_id` grants nothing, and load-balanced policies are resolved to a concrete child first.*

### 其他 / Also in this release

- **右键单个下载直连存储端**：文件列表右键「下载」对单个文件改为向服务端请求直连地址（而非本站中转地址），无 CDN 镜像时不弹选择框。
  *Context-menu "Download" on a single file now asks for the provider's direct URL; without CDN mirrors configured no route dialog appears.*
- **存储策略页未知类型优雅降级**：策略属性从 `StoragePolicySetting.tsx` 拆到独立的 `policyProps.tsx`，遇到不认识的策略类型（例如旧版本数据库里残留的类型）不再抛异常导致整页白屏，而是在编辑页顶部显示提示横幅、在策略卡片上打上「未知策略类型」标签，其余策略照常可用。
  *The policy properties move into `policyProps.tsx`; an unrecognised policy type (say, left over from an older database) no longer throws and blanks the whole page — the edit form shows a notice and the card is labelled "unknown policy type", while every other policy keeps working.*

## 调整 / Changes

- **打包（zip）在移动云盘策略下被拒绝**：直连策略没有可中转的字节流，打包只能逐个拉流，所以创建打包会话时就返回明确的错误（`archiving (zip) is disabled on the 139 cloud drive policy, download the files individually`），浏览器侧打包同样加守卫，不会静默退回中转。顺带修掉了这条错误此前会被 `fmt` 当成格式串、在错误正文里多出一段 `%!(EXTRA <nil>)` 的问题。
  *Archiving is refused on this policy with a clear error at session creation, since zipping would stream every entry through this site; browser-side zipping is guarded the same way. The previous `%!(EXTRA <nil>)` noise from formatting that message as a format string is fixed too.*
- **云盘地址不再被 CDN 镜像改写**：直连地址本就是这个文件最快的路径，且带有存储端自己的签名，改写只会让它失效；现在只有本站自己在服务的地址才参与镜像选择。
  *Direct storage URLs are no longer rewritten against CDN mirrors — they already are the fastest route and carry the provider's signature; only URLs this site serves take part in mirror selection.*

## 兼容性 / Compatibility

- 新增的存储策略类型是纯增量能力：不创建该类型策略的站点，升级后行为、数据与界面与 v4.23.6 完全一致。
- 上传采纳客户端指定策略属于行为修正——已按用户组允许集合校验，越权与不可用策略一律回退到原有选择逻辑；即使前端不传该字段，行为也与旧版一致。
- 右键单个下载改为直连后，浏览器会直接与存储端通信；存储端签发的地址在有效期内可直接访问，不走本站流量统计。
- *The new policy type is purely additive: sites that do not create one behave, store and look exactly as in v4.23.6. Honouring the client's policy choice is a correction gated by the group's allow-list, falling back to the previous logic otherwise; omitting the field keeps the old behaviour. Single-file downloads now talk to the storage provider directly and no longer count against this site's traffic stats.*

## 已知限制 / Known Limitations

- **移动云盘策略下不能打包下载**：zip 与批量下载不可用，只能逐个下载文件。
  *Archiving and batch download are unavailable on this policy; download files one by one.*
- **加密策略仍会中转**：加密存储必然需要本站在端侧做解密与加解密处理，无解。
  *Client-side-encrypted storage necessarily has to be processed here, so it still relays.*
- **历史 local 实体仍走中转**：老文件如果实体落在 local 策略（例如根目录下的历史文件），它没有上游可跳转，中转是正确行为；要直连请在移动云盘策略的目录下上传与下载。
  *Older files whose entities live on a local policy have no upstream to jump to, so relaying them is correct; use a directory bound to the drive policy for direct transfers.*
- **分片数上限**：云盘单次最多签发 100 个分片地址，官方客户端在 30 GB 以下用 100 MB 分片，建议分片大小填 100 MB（向导里默认如此）。
  *The drive signs at most 100 chunk URLs per upload and its own client uses 100 MB chunks below 30 GB; the wizard defaults the chunk size accordingly.*

## 升级 / Upgrade

**Docker / Docker Compose** — 只需换镜像：

```bash
docker pull ghcr.io/dark-cc/cloudreve:v4.23.7
```

或使用迁移脚本（自动备份 compose 文件、换镜像、重启）：

```bash
curl -sSL https://raw.githubusercontent.com/Dark-CC/cloudreve/baixiong/migrate.sh | sh -s -- /path/to/compose/dir
```

**二进制** — 从下方 [Downloads](#downloads) 下载对应平台压缩包，停止服务、替换二进制、重启即可。`data/` 目录（SQLite、上传文件、`conf.ini`）不受影响。本版没有数据库结构变更，但升级前照常建议先备份。

**启用移动云盘** — 升级后在「后台 → 存储策略 → 新建」里选择「移动云盘」，填入网页端登录凭据与 `x-yun-app-key`，保存后把用户组的允许策略与默认策略指向它（或在目录上绑定该策略）即可。

*Upgrading requires no schema change; back up as usual. To use the drive, create the policy in the admin wizard with the web login credential and app key, then allow it for a user group or bind it to a directory.*
