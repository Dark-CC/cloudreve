# Cloudreve v4.23.9

本版本修好了**极验人机验证在所有场景下必然失败**的故障（登录、注册、找回密码、举报、管理员二次验证一处不落），并让**站点公告可以写 HTML 格式**，同时在服务端做了严格的白名单过滤。自 v4.23.8 以来的全部变更如下。

This release fixes **Geetest human verification failing in every scenario it is enabled for** (sign-in, registration, password reset, abuse report and the admin step-up check), and lets the **site announcement carry HTML formatting** behind a strict server-side allow-list sanitiser. Everything changed since v4.23.8 is listed below.

## 修复 / Fixes

### 极验人机验证全部场景失效 / Geetest verification failing everywhere

- **根因是校验地址写错了，不是配置问题**：本项目的极验 v4 服务端二次校验请求发往 `api2.geetest.com`，该域名**已经不再解析**（NXDOMAIN）；回退地址 `api.geetest.com/v4/validate.php` 虽然存在，但被上游 CDN 的 WAF 拦截，返回的是 **HTTP 567 的拦截页**而不是极验的业务应答。于是无论用户人机验证做得多正确，服务端这一步永远拿不到结果，只能报「验证码错误」。
  *The verification request went to `api2.geetest.com`, which no longer resolves, and fell back to `api.geetest.com/v4/validate.php`, which is now intercepted by an upstream WAF and answers with an HTTP 567 block page instead of Geetest's business response. Correct human answers therefore never reached a verdict, and the server could only report a captcha error.*
- **改用极验官方 v4 校验端点**：现请求 `https://gcaptcha4.geetest.com/validate`（备用 `https://gcaptcha4.geevisit.com/validate`），这两个正是极验官方 gt4.js SDK 自己使用的 API 域名，路径为 `/validate`（不带 `/v4/`）。已用真实凭据实测：伪造票据会得到 `{"result":"fail","reason":"pass_token error"}` 这样的**正规业务应答**，说明请求已经真正进入极验的校验逻辑。
  *Verification now uses `https://gcaptcha4.geetest.com/validate`, with `https://gcaptcha4.geevisit.com/validate` as fallback — the same API hosts the official gt4.js SDK uses, at `/validate` (no `/v4/` prefix). Tested with real credentials: a forged ticket now returns a proper business answer (`{"result":"fail","reason":"pass_token error"}`), proving the request reaches Geetest's verifier.*
- **不再把「上游拦截页」误报成「验证码错误」**：解析应答前先确认它是一段 JSON，否则视为该端点不可用并尝试下一个端点；两个端点都被拦截时，日志里会明确写出是上游 WAF/CDN 拦截，而不是含糊的校验失败。这样下次同类问题可以一眼看出是端点坏了。
  *A non-JSON answer is now treated as an unusable endpoint and the next one is tried, instead of being parsed as a verdict. When every endpoint is blocked the log says so explicitly (upstream WAF/CDN), so the same class of outage is obvious next time.*
- **覆盖全部五个场景**：登录、注册、找回密码、举报滥用、后台设置的管理员二次验证共用同一段校验逻辑，一处修好即全部恢复；`login_captcha` / `reg_captcha` / `forget_captcha` / `abuse_captcha` 四个开关的任意组合都已实测。
  *All five call sites share one verifier, so one fix restores them all: sign-in, registration, password reset, abuse report and the admin step-up check, in any combination of the four settings toggles.*

## 新增 / What's New

### 站点公告支持 HTML / HTML in the site announcement

- **后台「站点信息 → 站点公告」可以直接写 HTML 了**：加粗、标题、列表、表格、链接、图片、引用等常用排版都能用，编辑框下方新增**实时预览**，看到的效果就是用户登录后看到的效果（多语言公告同样适用）。
  *The announcement field under Site information accepts HTML now — headings, bold, lists, tables, links, images, quotes — with a **live preview** underneath showing exactly what a logged-in user will see, per-language variants included.*
- **服务端白名单过滤，而不是把 HTML 直接放行**：公告是管理员编辑、却展示给**每一个已登录用户**的内容，一旦原样渲染，就等于给这个设置项开了一个存储型 XSS 的入口——一次误粘贴、或者一次管理员会话被盗，就会在所有人的页面里执行脚本、读取他们的会话与文件。因此公告在**写入和读取时都**经过同一个白名单清洗器，前端另有一道同规则的二次过滤。
  *Allow-list filtering on the server rather than raw passthrough: the announcement is admin-authored but shown to **every logged-in user**, so rendering it verbatim would make that field a stored-XSS sink — one bad paste, or one stolen admin session, would run script in everyone's page and reach their session and files. Content is sanitised on write **and** on read, with a matching second pass in the browser.*
- **允许的标签**：`a` `abbr` `b` `blockquote` `br` `caption` `center` `cite` `code` `col` `colgroup` `dd` `del` `details` `dfn` `div` `dl` `dt` `em` `figcaption` `figure` `h1`–`h6` `hr` `i` `img` `ins` `kbd` `li` `mark` `ol` `p` `pre` `q` `rp` `rt` `ruby` `s` `samp` `small` `span` `strike` `strong` `sub` `summary` `sup` `table` `tbody` `td` `tfoot` `th` `thead` `tr` `tt` `u` `ul` `var` `wbr`。
- **禁止的标签及理由**：`script` / `noscript` / `template` / `object` / `embed` / `applet` / `param`（执行或实例化代码）；`iframe` / `frame` / `frameset` / `portal`（叠加一个攻击者控制的页面，是钓鱼的主要手法）；`form` / `input` / `button` / `select` / `textarea` / `label` / `fieldset`（可在公告弹窗里伪造一个「请输入密码继续」的登录表单，是最直接的凭据窃取方式）；`meta` / `base` / `link` / `title` / `head`（改写相对地址或注入头部）；`svg` / `math` 及所有带命名空间的外来元素（历史上沙箱绕过最多的一类，且写公告用不到）；`style`（任意 CSS 可以盖住整个视口、隐藏真实界面，或通过 `url()` 外带数据）；`video` / `audio` / `source` / `track`（自动加载外部媒体）。
- **禁止的属性**：所有 `on*` 事件属性（`onclick` / `onerror` / `onload` …）一律丢弃；`style`、`srcdoc`、`formaction` 丢弃；带命名空间的属性（`xlink:href`、`xml:base` 等）丢弃；`href` / `src` 拒绝 `javascript:` `vbscript:` `data:` `blob:` `filesystem:` 协议（含插空制表符、HTML 实体等变形写法）。`target="_blank"` 自动补 `rel="noopener noreferrer"`，防止被打开的页面反向操纵本站窗口。
- **不认识的标签取内容、不取标签**：比如公告里写了 `<font color="red">重要通知</font>`，文字会保留、标签会去掉，不会把管理员写的话整段吞掉。
- **旧公告照原样展示**：不含任何标签的历史公告（纯文字或 Markdown）继续按 Markdown 渲染，升级后观感不变。
  *Legacy announcements without tags keep rendering as Markdown, so upgrading changes nothing for existing content.*

## 兼容性 / Compatibility

- 极验修复只改请求地址与应答判定，**后台配置不需要重新填写**，已保存的 captcha_id / captcha_key 继续有效。
- 公告的 HTML 支持是纯增量：不写标签的公告行为与 v4.23.8 一致；已存在的公告不需要任何迁移。
- 本次不涉及数据库结构变更，无需数据迁移；升级前照常建议先备份。
- *The Geetest fix only changes the endpoint and the response check — existing captcha_id / captcha_key settings stay valid. HTML announcements are additive, require no migration, and there are no schema changes. Back up first as usual.*

## 已知限制 / Known Limitations

- 公告的 HTML 白名单是**按标签与属性列举**的，不支持内联 `style`，也不支持在公告里嵌入视频、地图或其他 iframe 组件；需要跳转的外部内容请用链接。
- 极验校验端点依赖极验官方的公网服务可达性；若站点所在网络无法出网访问 `gcaptcha4.geetest.com`，登录等受保护的场景会失败，日志会明确记录为端点不可达/被拦截。
- *Inline `style`, embedded video, maps and other iframes are not supported in announcements; link out instead. The verifier needs outbound access to `gcaptcha4.geetest.com`; if the site cannot reach it, protected actions fail and the log records the endpoint as unreachable or intercepted.*

## 升级 / Upgrade

**Docker / Docker Compose** — 只需换镜像：

```bash
docker pull ghcr.io/dark-cc/cloudreve:v4.23.9
```

或使用迁移脚本（自动备份 compose 文件、换镜像、重启）：

```bash
curl -sSL https://raw.githubusercontent.com/Dark-CC/cloudreve/baixiong/migrate.sh | sh -s -- /path/to/compose/dir
```

**二进制** — 从下方 [Downloads](#downloads) 下载对应平台压缩包，停止服务、替换二进制、重启即可。`data/` 目录（SQLite、上传文件、`conf.ini`）不受影响。

**升级后建议**：浏览器强刷一次（或清掉站点数据）以确保前端资源与翻译缓存一并更新到本版。

*Docker users only need to swap the image; binary users stop the service, replace the binary and restart. `data/` is untouched. After upgrading, hard-refresh the browser once so the static assets and translation cache both move to this build.*
