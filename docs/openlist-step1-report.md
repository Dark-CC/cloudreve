# OpenList 存储策略 · 第一轮（只读连通 + 302 直连）

状态：**已完成并真机端到端验证通过**

## 一、本轮交付了什么

在 Cloudreve 中新增一种存储策略类型 **OpenList**，站长自建 OpenList 实例，本站只通过其 HTTP API 通信：

- **列目录**：读取远端目录树并导入索引，文件可正常浏览。
- **下载直连**：浏览器拿到的下载地址直接指向站长自己的 OpenList，字节流不经过本站。
- **上传/删除/重命名/移动/建目录/秒传/断点续传**：本轮不做，接口一律返回只读错误；前端上传入口对该策略类型直接拦截并提示。

OpenList 源码（AGPL-3.0）未并入本仓库，仅按其公开 HTTP API 调用。

## 二、配置项

| 配置 | 说明 |
| --- | --- |
| 服务器地址 | OpenList 实例根地址，如 `https://ol.example.com` |
| 用户名 / 密码 | 该实例的账号，用于换取访问令牌 |
| 挂载路径 | 该策略锚定在实例的哪个目录下，如 `/docs`；此目录即策略根，其外不可达 |

凭据当前以明文存于策略记录，加密列为独立轮次的技术债（见第七节）。

## 四、真机端到端验证结果

环境：本机起临时 OpenList 实例（独立端口、临时数据目录，验证后已停止并清理）＋ 本仓库二进制组成的 Cloudreve 实例，管理员建 OpenList 策略指向该临时实例，走正规导入通路建索引。

| 验证项 | 方法 | 结果 |
| --- | --- | --- |
| 列目录 | 触发导入任务，递归读取远端目录 | **通过**。识别 2 个文件 + 1 个子目录 + 1 个嵌套文件，全部导入成功，任务状态 completed |
| 目录内容正确性 | 核对 Cloudreve 中的文件列表与大小 | **通过**。`readme.txt` 21 字节、`big.bin` 300000 字节，与远端一致 |
| 下载直连 | 取文件下载地址并核对其指向 | **通过**。返回的地址是 OpenList 自己的签名直链（指向站长实例，带 sign 参数），非本站中转地址 |
| 字节不经本站 | 直接拉取该直链 | **通过**。300000 字节完整拉取，流量走站长实例 |
| 302 跳转链路 | 请求本站生成的分享/直链 | **通过**。返回 `302 Found`，`Location` 即该 OpenList 签名直链 |
| HTTP 200 内含业务错误 | 回放真实实例响应体 | **通过**。`object not found`、`storage not found`、令牌无效、路径越界四种情形均被正确判定为失败，不会误当成功 |
| 令牌 48h 过期自动重登 | 令牌进入续期窗口、以及服务端提前作废令牌 | **通过**。两种情况都会自动重新登录，后者重登后将原请求重试一次，用户无感 |
| 挂载子路径越界防护 | 请求含 `..` 的路径 | **通过**。在到达 OpenList 之前即被拒绝 |

补充：非 2xx 响应即使响应体内写着成功也判为失败；登录限速（OpenList 对反复失败登录返回的限速）被单独归类，提示管理员「稍后重试」而不是误导其去改密码。

## 五、验证中发现并修掉的三个问题

1. **登录无限递归**：登录请求本身走了带认证的发送路径，导致「发送 → 取令牌 → 登录 → 发送」自我调用直至栈溢出。已改为登录走未经认证的发送路径。
2. **令牌覆盖用户名**：原先设计把访问令牌写回策略的凭据槽位，而该槽位存的是用户名，写回后账号被令牌顶替，后续登录必然失败。**已推翻原设计**：OpenList 采用用户名+密码认证，令牌仅在内存缓存，过期或服务重启后重新登录即可，凭据始终在库里。
3. **挂载前缀被拼接两次**：传入的路径已含挂载前缀，驱动又加了一次，导致请求打到不存在的 `/<挂载>/<挂载>`。已改为先剥离前缀再请求，并补充了对应单元测试。
