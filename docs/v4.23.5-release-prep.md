## 三、Release 流水线适配（`.github/workflows/release.yml`）

1. **发版说明强制化**：server job 新增 "Verify release notes exist" 步骤——每个 `v*` tag 必须携带 `docs/release-notes/<tag>.md`，缺失则构建失败；GoReleaser 以 `--release-notes docs/release-notes/${{ github.ref_name }}.md` 将其作为 GitHub Release 正文。
2. **desktop job 门控**：`createUpdaterArtifacts: true` 硬性要求 `TAURI_SIGNING_PRIVATE_KEY` secret，Windows sparse identity 包需要 `SPARSE_SIGNING_PFX_*`。本仓库尚未配置这些 secrets，故整个 job 以仓库变量 `vars.DESKTOP_RELEASES == 'enabled'` 门控（GitHub Actions 的 job 级 `if` 不能引用 `secrets` context，用 vars 是标准做法）。配齐 secrets 并设置该变量后即可开启桌面端发布。`updater-manifest` job `needs: desktop`，会自动联动跳过。Windows sparse 签名步骤另加了 `env.SPARSE_SIGNING_PFX_BASE64 != ''` 守卫。
3. **android job 门控**：无 keystore secrets 时 Gradle 回退 debug 签名，不应出现在正式 release，故以 `vars.ANDROID_RELEASES == 'enabled'` 门控。
4. **触发方式不变**：`push: tags: ['v*']`；server 产物矩阵不变（linux amd64/arm64/armv5–v7/loong64、windows、darwin、freebsd + checksums.txt + GHCR 多架构镜像，用自带 `GITHUB_TOKEN` 建 Release、推 `ghcr.io/dark-cc/*`）。

**发版操作**：改动合入 `baixiong` 后，对 `baixiong` tip 打 tag `v4.23.5` 并推送即可（平台 `create_tag` 工具或手动 `git tag v4.23.5 && git push origin v4.23.5`），GitHub Actions 自动构建并发布。
