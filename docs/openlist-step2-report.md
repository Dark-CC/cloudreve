# OpenList 存储策略 · 第二轮（写入能力）

状态：**已完成并真机端到端验证通过**

## 一、本轮交付了什么

在上一轮（只读浏览 + 302 直连下载）之后，OpenList 策略现在可以正常写入：

- **上传**：小文件与大文件均可上传，大文件走分片，中断后可续传。
- **删除**：与本站其他策略一致，先入回收站，清空回收站时才真正删除远端文件。
- **重命名**：文件与文件夹都同步到远端。
- **移动**：文件与文件夹都同步到远端。
- **建目录**：见第五节，行为与本站既有策略一致。

秒传（秒传/极速转存）本轮不做，留待后续。WebDAV 挂载点随重命名/移动自动跟随。

## 二、上传是"经本站中继"的，这是一个安全决定

OpenList 的 HTTP API 只接受**账户自己的登录令牌**作为写权限凭证。把这个令牌发给浏览器，等于把站长 OpenList 账户的完整权限交给任何一个访问者——他们可以直接登录站长的 OpenList 后台。

因此 OpenList 策略**强制经本站中继**：浏览器的字节流先到本站，由本站以服务端身份写入 OpenList。策略设置里"中转上传"开关对该类型不生效，管理页面上也不显示它，改为一段说明。

### 为什么这对绝大多数 OpenList 用法没有代价

OpenList 支持 88 种底层存储驱动，其中**只有 4 种**（OneDrive 三个变体与 S3）实现了浏览器直传。也就是说，站长把 OpenList 挂在另外 **84 种**存储上时，OpenList 自身也不提供直传通道，"不经过中转"本来就做不到。

| 情形 | 上传路径 | 说明 |
| --- | --- | --- |
| 底层驱动实现了直传（4/88） | 仍经本站中继 | 令牌不能下发的安全约束优先 |
| 底层驱动未实现直传（84/88） | 经本站中继 | 与 OpenList 自身能力一致，无额外损失 |

无论哪种情形，**下载**仍然是浏览器直连站长自己的 OpenList（302 跳转），字节流不经过本站——第一轮的能力保持不变。

## 三、配置项

沿用第一轮，另新增两项可选：

| 配置 | 说明 |
| --- | --- |
| 服务器地址 | OpenList 实例根地址 |
| 用户名 / 密码 | 该实例的账号，用于换取访问令牌 |
| 挂载路径 | 该策略锚定在实例的哪个目录下 |
| 目录名规则 | 文件在挂载路径下的落盘目录规则，默认 `uploads/{uid}/{path}` |
| 文件名规则 | 落盘文件名规则，默认 `{originname}`（保持原文件名） |

两条规则与本站其他策略的同类设置含义一致，也支持相同的占位符。

令牌只在内存中缓存，过期或服务重启后自动重新登录；**不会写回策略记录**，策略里的账号密码始终原样保留。

## 五、验证中发现并修掉的问题

1. **重命名任何文件都会让请求崩溃**：重命名/移动前需要读取文件所属策略，而代码读取了一个未加载的字段，导致空指针。已修正，并补了回归测试覆盖"未加载"与"已加载"两种情况。
2. **重命名后文件地址失联（本轮最严重）**：本站重命名只改索引里的名字，而远端对象的路径是写入时记录下来的。改名后这串地址就过期了，**随后的下载、移动、删除都会找不到文件**——表现为移动报"源对象不存在"。已改为在远端的改名/移动完成后，按策略的路径规则重算受影响文件（含子目录内的全部文件）的地址并写回。
3. **移动的目标目录算错**：移动时传给远端的"目标目录"用的是本站的目录路径，而不是该目录在远端对应的位置，两者不同。已改为按目录规则换算，与上传时的落盘规则同源，避免再次分叉。

第 2、3 项只有在你实际去整理目录时才会暴露，属于本轮真机测试的主要收获。

## 六、建目录的现状（需要你知道）

本站新建目录**只在索引里建**，远端目录在你第一次往里上传文件时按需创建。这与本站既有策略（如本地存储、S3）的行为一致，也是 Cloudreve 的既有设计——它的驱动接口里没有"建目录"这一步。

对使用者的实际影响：建了空目录但什么都没放，远端看不到这个目录；一旦放了文件，整条路径就都出现了。如果你希望"建目录即同步"，可以单独做一轮。
